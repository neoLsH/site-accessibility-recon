# 检测向量全景（L0–L7）

`layers.md` 回答「这一层怎么判」；本文件回答「**这一层还有哪些信号没查**」。

这是一张查漏表，不是必测清单：从第一个失败的门所在层往下查，别从 L4 开始把所有探针跑一遍。

## 网络 / 链路（L1）

| 信号 | 怎么观测 | 常见误判 | 对策 |
|---|---|---|---|
| DNS 解析与泄漏 | `dig` 对照；代理下抓 DNS 查询，或改用 DoH | 代理只代理 TCP 不代理 DNS，查询暴露真实位置 | S4 |
| 出口身份（IP 信誉 / ASN / 地理） | 出口回显服务查 ip / asn / geo，对比不同出口 | 把机房 IP 的低信誉读成「站点反爬很强」 | S4 |
| 代理是否真挂上 | CONNECT 200 + TLS 握手 + 拿到源站响应体，三者齐备 | 配置齐全但内核不支持该 CDP 命令 → 实际是直连 | S4 |
| 稳定性噪声 | 5xx / 超时 / 连接重置**单独计数** | 把基础设施抖动计成拦截 | — |

## 传输（L2）

| 信号 | 怎么观测 | 常见误判 | 对策 |
|---|---|---|---|
| TLS 版本 / ALPN | `openssl s_client -alpn h2` | 只测 TLS1.2 就下结论 | S2 |
| ClientHello 指纹（JA3/JA3N/JA4） | 回显服务或本地抓包 | 换了 UA 没换栈，指纹仍是命令行工具 | S2 |
| 证书链 / SNI | `openssl s_client -servername` | 漏 SNI 拿到默认站点证书，误判链路异常 | S2 |
| H2 指纹（SETTINGS 帧参数 / 顺序 / 窗口） | 回显服务看 SETTINGS | headless 内核缺 GREASE、多出 ENABLE_PUSH | S2 |
| TLS 扩展顺序置换 | 内核启动开关 | 应用层改不了，误以为改 Header 有用 | S5 |

## 请求语义（L3）

| 信号 | 怎么观测 | 常见误判 | 对策 |
|---|---|---|---|
| Sec-Fetch-Mode / Dest / Site | 抓包对比导航与 XHR | 用 XHR 语义发导航请求，或反之 | S1 |
| UA ↔ client hints 版本 / 平台一致 | 两者并排比 | 只改 UA 不改 hints | S1 |
| Accept-Language / q 值 / Referer / Origin | 抓包 | q 值重复、语言与出口地域不符 | S1 |
| 请求发起方式（导航 / fetch / credentials 模式） | 同一 URL 换两种发起方式 | 默认导航语义撞上只放行 XHR 的策略 | S1 |
| 凭证注入通道 | header 注入 vs 浏览器 cookie 库；观察 302 是否覆盖 | 只走一条通道，被 302 的 Set-Cookie 覆盖 | S1 / L5 |
| 入口参数（来源 / 场景参数） | 同一资源换不同入口参数 | 把入口参数当鉴权——凭证过期时换参数无效 | S1 |

## 运行时 · 浏览器与内核（L4）

| 信号 | 怎么观测 | 常见误判 | 对策 |
|---|---|---|---|
| webdriver / plugins / languages | 页面内探针 | 只查 webdriver，漏掉语言 locale 这类硬 tell | S3 |
| 平台四维自洽（UA / platform / hints / WebGL） | 一次采集全比 | 只对齐 UA，platform 与 GPU 仍是内核默认值 | S3 / S5 |
| Canvas / WebGL / AudioContext / 字体枚举 | 指纹探针 | 软件渲染带来的熵被当成「随机噪声」 | S5 |
| 屏幕几何（screen / viewport / devicePixelRatio） | 探针 | screen < viewport 这类不自洽 | S3 |
| 时区 / Intl locale | 探针 | 容器时区为空 = UTC，与出口地域冲突 | S3 / S5 |
| WebRTC ICE | 探针看候选地址 | 以为代理生效，实际 ICE 泄漏真实 IP | S3 / S4 |
| CDP 痕迹 | Error.stack getter、Proxy ownKeys 探针 | 只查 webdriver，不查调试协议侧 | S3 |
| 启动参数（有害项 / 隐身项） | 逐项开关做对照 | 禁用 WebGL 反而暴露「这不像真浏览器」 | S3 / S5 |
| GPU / 软件渲染 | WebGL renderer 串、渲染耗时 | 忽略软件渲染与硬件渲染的差异 | S5 |
| 采集上报通道 | 抓包找非常规 POST / beacon，abort 后看是否改判 | 把「采了」当成「判定用了」 | — |

## 业务凭证（L5）

| 信号 | 怎么观测 | 常见误判 | 对策 |
|---|---|---|---|
| token 三层（签名 / 时效 / 内容） | 分别构造：无 token / 旧 token / 新 token | 把「过期跳登录」读成「必须登录」 | S7 / S0 |
| 设备标识类凭证 | 追踪生成方、生命周期、清空后是否再生 | 每请求新生成，导致无法关联 | S1 / S7 |
| 一次性凭证 | 重放同一凭证看第 2 发 | 冻结重放被当成「凭证无效」 | S1 |

## 服务端决策（L6）

| 信号 | 怎么观测 | 常见误判 | 对策 |
|---|---|---|---|
| per-resource | 同 session 不同 URL | 用一个 URL 的结论覆盖全站 | S0 |
| per-IP / per-node | 跨出口、跨节点分布对比 | 把节点差异读成站点策略 | S4 |
| 累积风险分 | 首次正常 → 多次后被拦 → 重启恢复 | 把累积降权读成不可复现的「概率门」 | S3 / S4 |
| 闸门正交组合 | 交叉矩阵 | 单变量实验得出「这个因素无关」 | S0–S5 |

## 三条使用规则

1. **按第一个失败的门所在层开始**，不要从 L4 开始铺探针。低层没通时，高层的「正常」只是没走到。
2. **同层多信号 = 可能多门并联**。一次只改一个，必要时做交叉矩阵；否则单变量实验会得出错误结论。
3. **表里没有 ≠ 不存在**。出现表外信号先记 `observed`，复现后再升 `mechanism`；不要因为表里没有就忽略。
