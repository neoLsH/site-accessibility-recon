# 三态分诊与闸门图

## 为什么先分诊

同一个表象（“页面空的”“打不开”）可能来自三种互斥的原因。它们的对策完全不重叠：

| 态 | 本质 | 对策方向 |
|---|---|---|
| A 链路失败 | 请求没到源站 | 修 DNS / 代理 / 网络 |
| B 反爬拦截 | 到了源站，被风控层挡下 | 过对应闸门，或换数据源 |
| C 内容业务状态 | 正常到达、未被反爬，内容本身如此 | 按删除 / 审核 / 权限 / 地域处置 |

判错的代价：把 A 当 B，会去无休止地调指纹；把 C 当 B，会把“内容没了”记成“被封锁”，指标永久失真。

---

## 三态判据

### 态 A：链路失败

- 最终 URL 是错误页（`chrome-error://` 之类）。
- 代理场景：`curl -x` 拿不到 CONNECT 200 / TLS 握手失败。
- 渲染接口返回成功码，但响应体极小且无任何站点特征。
- 请求计数为 0，或内核日志提示代理相关 CDP 命令不存在。

**注意**：短链 302 经代理时响应体为 0 是正常的，不要误判为失败。

### 态 B：反爬拦截

- 极小 / 非标准响应体，或明显的挑战页、验证码页。
- 风控 / CDN 产品自有的响应头字段，或异常的 `server` 标识。
- 跳转到登录 / 验证 / 挑战类的特征路径，或带风控参数的 403 / 404 落地页。
- 业务层的风控码，与“内容不存在”的业务码**不是一套枚举**。

### 态 C：内容业务状态

- 前端拿到明确业务码后渲染的文案：“内容不存在”“审核中”“无权限”“地区不可用”。
- HTTP 200，最终 URL 正常，页面结构完整，只是目标实体不可见。
- 换出口、换客户端、换凭证都不改变结果。

**处置**：回溯业务码，定位是删除 / 审核 / 权限 / 地域，据此判断可解性。不要笼统记成“被封”。

### 边界情况

- **降级软拦截**：HTTP 200 + 元信息齐全 + 内容区被抽空。它属于态 B，但表象像态 C，必须量**内容区**才能识别。
- **登录墙**：可能是态 B（反自动化），也可能是态 C（权限），用“真实浏览器匿名是否可见”区分。

### 兜底判据：两类落在缝里的样本

上面的判据覆盖大多数样本，但有两类会同时像多个态。**它们必须走下面的判别序列，不能凭“响应体小”直接记成态 B**——那会触发最贵的一条错路：去调指纹。

#### 样本类型 1：HTTP 2xx，但内容区为空

同一个表象有四个来源，对策完全不同：

| 来源 | 本质 | 归到 |
|---|---|---|
| 边缘返回外壳，正文被替换 / 抽空 | 降级软拦截 | 态 B |
| 源站有正文，但抽取器 / 你这一层丢了 | 观测链路问题 | **不归反爬** |
| 正文靠 JS 渲染，原始 HTML 里本来就没有 | 需要浏览器，不是拦截 | **不归反爬** |
| 实体本身不可见，页面渲染“内容不存在” | 业务状态 | 态 C |

判别序列（按序执行，任一步即可分流）：

| 步 | 动作 | 判定 |
|---|---|---|
| 1 | 量**原始 HTML** 中内容容器的字符数（不是抽取后的 markdown / 纯文本） | 容器有正文 → **抽取下游丢失**，去查抽取链路；容器不存在 / 为 0 → 进第 2 步 |
| 2 | 同一 URL 用真实浏览器取内容区长度，并加一组**禁用 JS** 的浏览器对照 | 禁用 JS 也是空、开 JS 有正文 → **需要水合，不是拦截**；禁用 JS 仍有正文 → 你缺的是运行时能力，不是反爬 |
| 3 | 开 JS 的浏览器也空 | 进第 4 步 |
| 4 | 换出口 / 换客户端栈，各 ≥3 pass | 结果随出口或栈翻转 → 态 B 软拦截（大概率是概率门）；始终为空且页面结构完整 → 态 C |

第 1、2 步的命令（脚本已内置，不必自己写解析）：

```bash
# 跑矩阵时留存原始 HTML，再用同一选择器离线复核
scripts/client-matrix.sh "$URL" --selector "#content" --save-html ./raw
scripts/client-matrix.sh --html ./raw/p1-curl-chrome.html --selector "#content"

# content 列：N=有正文 / 0=容器在但空 / missing=页面里没这个容器
#            ?unsupported=选择器太复杂，改用真实浏览器取值
```

**分水岭是第 1、2 步的组合**：原始 HTML 为空不等于被拦，还要排除“这本就是 CSR 页面”。整页长度不能替代内容区长度——降级外壳整页也能有数千字符，抽出几百字照样是空的。同理，报告 / 日志里存的“内容预览”常被截断，不能用来判定完整性。

#### 样本类型 2：极小响应体的 4xx

它表面上符合态 B 的“极小响应体”，但可能是链路层生成的错误页。按内容定态：

- 有风控 / CDN 特征头、或明确的拒绝文案 → **态 B 硬拒**。这类通常不是伪造能解决的，杠杆在换出口 / 换栈；先按对策阶梯的 S0 考虑换数据源。
- body 极小（<1KB）、不含 HTML 结构、也没有任何站点特征 → 按**态 A 链路失败**复核：对同一 host 的同源静态资源（如 `/robots.txt`、`/favicon.ico`）发一次请求。
  - 静态资源也失败 → 确实是链路 / 出口问题（态 A）。
  - 静态资源正常、只有目标路径 4xx → 请求到了源站，回到**态 B 硬拒**（或业务 404，需看文案）。
- body 是完整业务页 → 用页面里的业务码定态 C。

“**站点特征**”指能证明响应来自目标源站的任意一项：目标域名的 TLS 证书、响应里的 canonical / og:url、本站自有静态资源域名、页面 title 含站点名。三项都没有，就默认按链路层生成页处理。

判定的通用要求：任何“小响应体”结论都要附上 `http + bytes + 是否含站点特征`，只写“空了 / 被拦了”无法回溯。

## 闸门图

### 构造方法

对每个已确认的闸门记一行：

| 字段 | 说明 |
|---|---|
| 闸门 | 一句话命名，如“TLS 栈白名单”“UA 字符串规则”“签名时效” |
| 判据 | 怎么观测，观测到什么值算不过 |
| 维度 | 出口 IP / 客户端栈 / 请求语义 / 运行时身份 / 凭证 / 账号 |
| 正交性 | 与哪些闸门独立；是否已验证交叉矩阵 |
| 状态 | 已过 / 已证不过 / 假设 |
| 成本 | 满足它要付出的代价与影响面 |

### 正交性是最容易踩的坑

两扇门**并联**时，只修一扇不会有任何效果，实验会得出“这个因素无关”的错误结论。

典型：某站同时校验 UA 字符串与 TLS 指纹。

```
Chrome-TLS + Chrome-UA → 拦
Chrome-TLS + Safari-UA → 过
Safari-TLS + Chrome-UA → 拦
Safari-TLS + Safari-UA → 过
```

单看“换 UA”或“换 TLS”都只能解释一半现象，必须做**交叉矩阵**。

### 第一个门主导观测

请求在第一个过不去的门就终止了。所以：

- 低层未通过时，**不要**对高层下结论。
- 低层修好后，**必须重测**高层，因为之前的“高层正常”可能只是没走到。
- 多个门同时存在时，先修**成本最低**的那个，再复测剩余。

### 确定性闸门 vs 概率门

| 类型 | 特征 | 验证方式 |
|---|---|---|
| 确定性 | 同条件必过 / 必不过 | 单次对照即可定性 |
| 概率门 | 同一 URL 跨次在“通过 ↔ 拦截”间翻转 | ≥3 pass，报区间与翻转率 |

概率门常见于“运行时身份 + 出口信誉 + 上下文状态”的组合评分。对概率门：

- 禁止用小样本点估计报良率。
- 区分“机制触发”与“转化”：重试真的跑了，不等于这次拿到了内容。
- 记录翻转率本身，它是模型敏感度的指标。

### 由现象反推层级

| 现象 | 优先怀疑 |
|---|---|
| 极小响应体、非标准格式 | L1 链路 或 L2 传输 |
| 标准错误格式、跳验证码 | L2/L3 |
| 有/无 cookie 结果不同 | L3/L5 |
| 同 session 不同 URL 结果不同 | L6（per-resource 风控） |
| 跨 pod / 跨出口分布不均 | L6（IP / 节点级） |
| 首次正常、多次后被拦、重启恢复 | L6（累积风险分） |
| 内容区为空但页面 200 | 先走「样本类型 1」判别序列：抽取下游 / 软拦截 / 态 C |
| 4xx 但响应体极小 | 先走「样本类型 2」判别序列：态 A / 态 B 硬拒 / 态 C |
