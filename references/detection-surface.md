# 判定面：客户端采集 vs 服务端评分

同一句「被拦了」，修复杠杆可能完全相反。**先定判定面，再谈改什么**：在错误的面上优化，投入是零收益。

三条铁律：

1. **采集 ≠ 判定。** 站点采集 40 个字段，进模型的可能只有 3 个。只有拔掉某个信号看结果是否翻转（ablation），才能证明它在决策路径上。
2. **上报 ≠ 同步判定。** 异步打分表现为「头几发正常、之后开始拦」，极易被读成「累积风险」或「指纹突变」。
3. **服务端判定不可用前端手段消除。** 一旦同一份字节流换出口就翻转，前端层的所有努力都是零收益——这也是「何时停手」的硬证据（见 [countermeasure-ladder.md](countermeasure-ladder.md)）。

## 三个判定位置

| 位置 | 能看到什么 | 看不到什么 | 典型形态 | 你能动的 |
|---|---|---|---|---|
| 边缘 / 网关（请求未进业务） | 出口 IP/ASN/地理、TLS/H2 指纹、HTTP 头与 URI、频率与并发、它签发的挑战凭证 | 页面内 JS 算出的指纹（除非经挑战回传）、账号身份、业务上下文 | CDN 的 bot 管理、WAF、限流 | 换协议栈、换出口、降频 |
| 前端采集 → 后端判定 | JS 能读到的全部浏览器侧信号、上报时附带的 token | 握手层指纹、跨会话历史 | 自建风控 SDK、设备指纹服务 | 对齐或关掉某个采集项、改上报 payload |
| 纯后端评分 | 会话历史、请求序列与节奏、账号年龄与信用、跨端关联、业务行为分布 | 单次请求的细粒度浏览器属性（除非前端上报） | 账号风控、反刷、反爬评分 | 满足条件：合法凭证、降频、换账号 |

三段常常**叠加**：边缘先廉价筛一遍，过了才进业务侧的采集+评分。所以「改了一个信号没效果」，很可能是更早的那道门还堵着——先回到 [triage-and-gates.md](triage-and-gates.md) 的正交性。

## 先分清：TLS/H2 指纹不是 JS 采集的

握手发生在任何 JS 执行之前。JS 只能读到浏览器「自述」的东西（UA、client hints、平台、时区），读不到 ClientHello，也读不到 H2 SETTINGS。

这条直接决定你在哪一侧投入：

| 观测 | 结论 |
|---|---|
| 只换客户端栈就翻转，改 JS 无变化 | 判定在边缘，看的是握手层（L2） |
| 只改 JS 侧产物就翻转，换栈无变化 | 判定在采集上报，看的是 JS 采到的字段（L4） |
| 换栈、改 JS 都无效，换出口才翻转 | 判定在服务端，看的是 IP / 信誉 |
| 三者都无效，只有「慢慢点」能过 | 判定在时序 / 轨迹 |

这条也解释了最常见的错判：拿 headless 的 TLS 指纹去解释一个只读 `navigator.webdriver` 的站点。

## 怎么证明在哪一侧：五个实验

前提不变：一次只动一个变量，留对照组，留 ≥3 pass，记录写进 `evidence.csv`。

### E1 固定客户端产物，只换出口

- **做法**：同一份请求（同栈、同 UA、同 cookie、同间隔）从 2 个以上出口各发一轮。
- **判读**：翻转 → 服务端按 IP/ASN/地理判定，走 S4；不翻转 → 出口不是主因，别在这里花钱。
- **陷阱**：一次性凭证可能与 IP 绑定，换出口会断链，看起来像「换了更差」。先确认凭证是否 IP 粘滞。

### E2 固定出口与产物，只改节奏与序列

- **做法**：同样请求分「背靠背 / 秒级 / 分钟级」三组；再补一组只改访问顺序（先列表后详情 vs 直打详情）。
- **判读**：静置恢复 → 速率或累积分；始终第 N 条失败 → 配额；永不恢复 → 静态判定，不是累积。
- **陷阱**：把「越测越差」读成「指纹被识别」。这是节流问题，见 [evidence-matrix.md](evidence-matrix.md)。

### E3 拦掉上报端点

- **做法**：找出采集上报的那个请求（通常是 POST 到非常规路径、体积小、body 是密文或 base64），在客户端把它 abort 掉。
- **判读**：改判 → 上报 payload 在决策路径上，判定是「采集 + 后端」；不改判 → 采集是遥测或旁路。
- **为什么它最干净**：只删了一个请求，其余字节完全不变，因果链最短。

### E4 逐项 ablation 采集项

- **做法**：一次只把一类采集 API 固定成「正常浏览器的典型值」，或让它返回空，看是否改判。
- **顺序**：自动化/调试痕迹 → 图形（canvas/webgl/audio）→ 环境（语言/时区/几何）→ 事件采样。
- **判读**：改判即证明该字段进模型；无变化就是「采了不用」。
- **陷阱**：固定成另一种不自洽的值会引入新 tell。改一项，验一项，别批量。

### E5 真实人工 vs 自动化

- **做法**：同出口、同账号，人工在真实浏览器操作 vs 脚本操作同一路径。
- **判读**：人工过、自动化不过，且 E4 已对齐采集项 → 判定在行为/轨迹，或内核侧痕迹（CDP、渲染特征）。杠杆回到 S3 运行时卫生，不是继续堆 JS 补丁。

## 前端采集面：六类信号

`scripts/js-surface.py` 把「站点 JS 里出现了哪些采集调用」列成表，并给出先 hook 哪几个。

| 类 | 典型 API | 为什么它可能在决策路径上 |
|---|---|---|
| 自动化 / 调试痕迹 | `navigator.webdriver`、`__playwright`、`chrome.runtime`、`permissions.query` | 最廉价、区分度最高的 tell |
| 图形 | `toDataURL`、`getImageData`、`WEBGL_debug_renderer_info`、`OfflineAudioContext`、`measureText` | 软件渲染与字体缺失暴露容器环境 |
| 环境 | `hardwareConcurrency`、`deviceMemory`、`screen.avail*`、`Intl.DateTimeFormat`、`getHighEntropyValues`、`RTCPeerConnection` | 与 UA、出口地域交叉验证自洽性 |
| 行为 | `mousemove` / `keydown` / `scroll` 采样、`visibilitychange` | 人机差异，且不依赖环境伪装 |
| 上报通道 | `sendBeacon`、`new Image()`、`fetch` 到非常规路径、`WebSocket` | 找到它就找到了 E3 的靶子 |
| 混淆与加密 | `CryptoJS`、`JSEncrypt`、`atob/btoa`、`_0x…` 字符串数组 | payload 不透明时，先定位，不急着还原 |

**静态命中 ≠ 运行时会调用。** 代码在包里不等于在当前页执行：先看命中，再在页面上下文给这些 API 装计数代理，记录调用栈首帧。静态负责「去哪找」，动态负责「真的采了什么」。

```bash
scripts/recon.py surface https://example.com/page          # 同源脚本，默认最多 8 个
scripts/recon.py surface --js recon/raw/app.bundle.js      # 直接扫一个 bundle
scripts/recon.py surface --html recon/raw/p1-curl.html     # 离线只扫内联
scripts/recon.py surface https://example.com/page --all-origins --json
```

**本 skill 到定位为止**：去混淆、还原加密算法、破解签名参数属于逆向工程，是另一类工作（工具选型见 [toolbox.md](toolbox.md)）。本文只回答「采集了哪些、哪几个进了模型」。

## 服务端评分面：五类信号

服务端看不到你的 canvas，但能看到更多你以为它看不到的东西：

| 类 | 信号 | 怎么单独验证 |
|---|---|---|
| 出口 | IP 信誉、ASN、地理、是否机房/代理 | E1 |
| 频率与并发 | QPS、突发度、连接复用方式 | E2 |
| 序列与轨迹 | 访问顺序、Referer 链、深度/广度、停留 | 固定出口只改顺序，看是否只有乱序才被拦 |
| 会话与账号 | 会话年龄、历史成功率、凭证签发次数 | 换新会话/新账号，指纹完全不变 |
| 跨请求关联 | 同一指纹跨 IP / 跨账号出现、设备 ID 复用 | 同一指纹从两个出口打，看是否互相污染 |

**指纹在这里常常只是关联键，不是阈值。** 服务端拿它把多个请求、多个身份串成一个「设备」，再用这个设备的整体行为（频率、覆盖度、成功率）打分。这解释了一类反直觉现象：单次请求的指纹完全正常，但同一个指纹第一次出现就被拦——它和一个已知的采集集群挂了同一把钥匙。

## 现象 → 优先怀疑

| 现象 | 优先怀疑 |
|---|---|
| 首次访问就拦，换出口有效 | 边缘按 IP/地理（E1） |
| 首次访问就拦，换出口无效但换栈有效 | 边缘按握手层（L2） |
| 前几发正常，之后开始拦，静置恢复 | 服务端累积分 / 频率（E2） |
| 上游页面正常，直打详情页被拦 | 序列 / Referer 依赖（E2 变体） |
| 拦掉某个上报请求就恢复 | 前端采集进了模型（E3） |
| 人工能过、脚本不能，且采集项已对齐 | 行为 / 轨迹或内核痕迹（E5） |
| 同一指纹换账号也立刻被拦 | 跨请求关联，指纹被当关联键 |
| 换什么都没用，只有官方 App 能看 | 判定在业务鉴权，转 S0 / S7 |

## 边界

- 这里的 hook 与 ablation 只用于**定性**：回答「信号在不在决策路径上」，不是「怎么伪造过去」。
- 不提供去混淆、算法还原、加密参数破解、验证码求解的做法。
- 所有实验仍受 [SKILL.md](../SKILL.md) 红线约束：只测有权测的目标，遵守 robots / ToS / 限速。
