# 会话状态：本轮内的 Cookie 连续性

真实访问里，服务端常在首跳种下一个会话标识，后续页面靠它认人。没有这个状态时，
同一套客户端臂会把“正常会话”误判成拦截。本层只解决这一件事：**让同一条臂在同一次
运行内，对同一个 host 保留服务端自己下发的 cookie**。

它不解决登录、不解决鉴权、不解决挑战；这些仍然走业务授权与人工路径。

## 边界

| 做 | 不做 |
|---|---|
| 保留本进程中目标站点下发的 cookie | 不落盘、不跨进程、不复用上次运行的会话 |
| 按 `(臂, host)` 各存一份 | 臂之间、host 之间互不可见 |
| 存到临时目录、文件 `0600`、退出即删 | 不写进证据行、试验行、策略档案或表格输出 |
| 只读服务端响应里的 `Set-Cookie` | 不构造、不伪造、不导入外部 cookie 或凭证 |

会话目录名与文件内容都不出现在 stdout/JSON 里；调用方只拿路径或会话对象。

## 生命周期

一次命令 = 一个会话周期。`ArmSession` 创建时分配临时目录
（`recon-cookies-<随机>`），命令结束时 `close()` 删除；即使调用方忘记关闭，
对象回收时也会清理。

- `native` 臂：每条臂每个 host 一个 Netscape 格式 jar，`curl -b/-c` 读写同一文件。
- `cffi:<profile>` 臂：每条臂每个 host 一个 `curl_cffi` 会话对象。
- 外部渲染臂（`browser:<engine>`）：会话由适配器自己负责，本层不注入。
- 未安装 `curl_cffi` 时该臂不可用，与是否开启会话无关。

## 各能力点的默认值

| 能力点 | 默认 | 关闭/开启方式 | 理由 |
|---|---|---|---|
| `crawl` | 开启 | `--no-cookies` | 连续页面共享会话，减少误判 |
| `fetch` | 开启 | `--no-cookies` | 多 URL 批量时贴近真实浏览 |
| `quick` | 开启 | `--no-cookies` | 跨 URL 学习时保持同一身份 |
| `matrix` | **关闭** | `--cookies` | 矩阵要逐臂独立对照，串味会污染结论 |
| `canary` | 不持有 | — | 基线要求可复现，不能有跨 pass 状态 |

`matrix` 的 opt-in 是刻意的：矩阵回答“同一次请求下哪条臂能取到”，一旦后一次尝试
继承了前一次的状态，比较就不再成立。要看会话带来的差异，分别跑
`matrix` 与 `matrix --cookies` 两轮，再看同一路由的翻转。

`quick` / `crawl` 同理：如果怀疑结果来自会话而不是客户端栈，加 `--no-cookies`
复跑一次，两轮的差值才是会话的贡献。

## 读法

- 第一页 `blocked`、同一臂第二页 `ok`：先怀疑会话，而不是立刻归因为“臂升级了”。
- `--no-cookies` 下仍然 `ok`：会话不是必要条件，结论更稳。
- 会话开启只影响 `native` / `cffi` 的 HTTP 采样，不影响 robots 判定、节流、熔断、
  臂暂停与策略更新；这些护栏照旧按请求计数。
- 证据行里的 `outcome`、`context`、`cost_ms` 不含任何 cookie 信息，跨轮对比仍然可行。

## 合规

会话只用于“同一站点、本轮内、服务端主动下发”的状态延续。以下都不在本层范围内：
绕过登录或付费墙、复用他人会话、导入 cookie 池、求解验证码、规避站点限速。
遇到 `robots: deny` 时仍然一个请求都不发，与是否开启会话无关。
