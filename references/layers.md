# 分层判据与探针（L0–L7）

按 L1 → L5 自底向上排查。每层只回答一个问题，答完再上一层。

本文件讲「这一层怎么判」；某层具体还有哪些信号没查，见 [vectors.md](vectors.md)（查漏表）。

---

## L0 口径层

**问题**：测什么，怎么算成功？

开工前必须写下来，否则后面所有数字都不可比：

- **URL 集合**：按路由分组（列表页 / 详情页 / 搜索 / 个人页 / 短链）。不同路由的风控等级常常完全不同，必须分开统计。
- **成功定义**：拿到目标实体的真实内容（不是“HTTP 200”，也不是“页面有内容”）。
- **完整定义**：内容区达到该路由的正常量级，未降级为空壳、导航、广告或登录引导。
- **样本量与重复次数**：单 URL 不能代表全站；同一 URL 至少 3 个 pass。

**典型误判**：拿一个 URL 的结论推全站；把“能打开页面”当作“能取到数据”。

## L1 链路层：请求到源站了吗

**判据**

| 信号 | 含义 |
|---|---|
| 最终 URL 是错误页（如 `chrome-error://chromewebdata/`） | 导航失败，不是内容问题 |
| 响应体极小且无业务特征（约几十字节） | 可能是链路失败，也可能是硬拦截，需结合 L2 |
| 代理下 `curl -x` 无 CONNECT 200 / 无 TLS 握手 | 代理未真正生效 |
| 代码返回“成功”但请求计数为 0 | 请求根本没发出去 |

**探针**

```bash
curl -v -x "$PROXY" -o /dev/null -w '%{http_code} %{size_download} %{url_effective}\n' "$URL"
```

代理要“CONNECT 200 + TLS 握手成功 + 拿到源站响应体”三者齐备才算通。短链 302 经代理时 body 为 0 属正常。

**典型误判**

- 把链路失败当“内容 thin / 被降级”。成功码 + 极小响应体时，必须先看最终 URL。
- “配置写了就等于生效”。内核缺少对应 CDP 命令时，代理配置齐全但请求没走代理。用请求计数与 `curl -x` 双重佐证。

## L2 传输层：边缘认这个客户端栈吗

**问题**：不是“TLS 有没有问题”，而是“**我这个运行时的 TLS/H2 栈**在这个边缘能不能过”。

**判据**：同一个 UA、同一个出口 IP，只换客户端栈，结果是否翻转。翻转即证明存在传输层闸门。

**客户端栈矩阵**（必须覆盖你自己的生产运行时）

| 客户端 | TLS 栈 | 用途 |
|---|---|---|
| 原生 `curl` | OpenSSL / LibreSSL / SecureTransport | 基准 |
| `curl_cffi impersonate=chrome` | BoringSSL（浏览器指纹） | 验证是否纯指纹问题 |
| `curl_cffi impersonate=safari` | BoringSSL（另一种指纹） | 排除“只放行某一种浏览器指纹” |
| Node `undici` / `fetch` | OpenSSL | **生产 http-document 的真实栈** |
| Python `requests` | OpenSSL（urllib3） | 同上 |
| headless Chromium | BoringSSL | 浏览器路径 |
| 真实浏览器 | BoringSSL | 对照组 |

**观测点**：状态码、字节数、最终 URL、响应中的风控标记。

**典型误判**

- 只测 `curl` 和 `curl_cffi`，两者 TLS 恰好都能过，于是得出“与 TLS 无关”的结论——而生产用的 Node 栈其实被拦。
- 从“内容 100% SSR”推出“HTTP 抓取可行”。SSR 只说明不需要 JS 水合，不说明你的客户端栈被放行。
- 把 H2 指纹与 TLS 指纹混为一谈。两者可以分别被判定：JA3/JA4 看 ClientHello，H2 看 SETTINGS 参数与帧顺序。

## L3 请求层：这次请求“像不像”正常请求

**判据维度**

| 维度 | 关注点 |
|---|---|
| UA 与 Client Hints | 版本号必须一致；平台字段要与 UA 自洽 |
| `Sec-Fetch-*` | 导航（`navigate`/`document`）与 XHR（`cors`/`empty`）会被区别对待 |
| `Accept-Language` | 不要出现重复 q 值等畸形结构 |
| Cookie | 是否被 302 的 `Set-Cookie` 覆盖；是否需要多通道注入 |
| 路由形态 | 桌面页 vs 移动页、详情页 vs 列表页、短链 vs 直链 |
| 请求方式 | 主文档导航 vs 同源 XHR，风控策略常常不同 |

**核心实验**

1. 用同一 URL 分别以“导航”和“XHR（同源、省略凭证）”请求，比较是否被重定向 / 拦截。
2. 用 `curl` 复刻浏览器的完整 header 集与顺序，若结果翻转，说明是 header 语义而非传输层。
3. Cookie 双通道注入：既通过浏览器的 cookie 设置接口写入，也在请求头里带 `Cookie`。只做前者时，常被响应里的 `Set-Cookie` 覆盖。

**典型误判**

- Header 顺序无所谓。某些边缘会按顺序与完整性打分。
- 注入了 cookie 就等于带上了 cookie。服务端跳转下发的新 cookie 会覆盖你预注入的值。

## L4 运行时层：这个浏览器“像不像”真人

**判据**：不是“有没有加 stealth 参数”，而是**各项身份是否互相自洽**，以及**你自己的自动化工具留下了什么痕迹**。

| 维度 | 检查点 |
|---|---|
| 自动化标记 | `navigator.webdriver`、`--enable-automation` 残留 |
| CDP 痕迹 | 你是否 `Runtime.enable`、是否订阅了不用的域、`Error.stack` 是否可被探测 |
| 图形栈 | WebGL vendor/renderer、Canvas/音频熵、是否软件渲染 |
| 环境自洽 | UA ↔ `navigator.platform` ↔ Client Hints ↔ WebGL ↔ 时区 ↔ 语言 ↔ 屏幕几何 |
| 几何 | `screen ≥ outer ≥ inner`，物理上必须成立 |
| 字面自洽 | UA 声称的系统要与 GPU、字体、时区、语言一致 |

**探针**：`scripts/fingerprint-probe.js`，在页面上下文执行，输出一份可 diff 的快照。

**关键认知**

- **自洽是必要条件，不是充分条件。** 把 UA/平台/WebGL/时区/语言/几何全部对齐后，目标站的墙可能依然存在。
- **先审计自己，再指责目标。** 很多“内核层无解”的结论，实际是应用层自己 `Runtime.enable` 留下的可探测痕迹。删掉零收益的 CDP 调用，往往比堆 JS 指纹伪造更有效。
- **不要在策略层伪造与内核真身冲突的指纹。** 内核真实平台是 A，JS 层伪造成 B，会制造新的不自洽，比不伪装更糟。
- **内核改不动的东西**（真实 GPU 渲染、二进制内置的伪装串）不要用 JS 补丁硬凑。

**典型误判**

- 用检测站点分数当“能过目标站”的证据。检测站点只测已知向量，不等于目标站的模型。
- 指纹自洽就当问题解决。必须回到目标站做活体 A/B。

## L5 业务层：凭证、签名、权限够不够

**token 三层判据**（带签名 / 有时效的凭证都适用）

```
无 token 或签名错  → 签名层拒绝：跳到风控页 / 404?source=...
签名对但已过期    → 时效层拒绝：跳到登录页（登录墙 ≠ 真需要登录）
token 有效        → 内容层放行：SSR 直出
```

**登录墙的三种成因**，对策完全不同：

1. 确实需要登录（权限）。
2. token 过期，服务端用“跳登录”表达拒绝。
3. 反自动化识别，用“跳登录”当软拦截。

区分方法：换新鲜凭证 / 换真实浏览器 / 换出口，看是否解除。若真实浏览器匿名可看，而自动化必跳，就是第 3 种。

**凭证生命周期**（每个关键 cookie 都要回答）

- 谁生成：服务端 `Set-Cookie` / 客户端 JS / SDK？
- 何时生成：首访 / 特定 API / SDK 初始化？
- 有效期：会话级 / 分钟轮换 / 天级 / 年级？
- 是否一次性：**冻结后重放还成立吗？**
- 绑定关系：是否与 IP、会话、UA 绑定？

**典型误判**

- 登录墙 = 必须登录。多数情况下它只是拒绝的表达方式。
- cookie 可以冻结复用。存在“逐响应滚动签发的一次性 nonce”，冻结重放第二发即失效；正确形态是**写回链**（每跳存 `Set-Cookie`，下一跳回放）。
- 一次性 nonce 可以与“每请求轮换出口 IP”共存。若 nonce 与 IP/会话绑定，轮换会直接断链，必须改成按 IP 粘滞串行。

**采集类站点的入口优先级**

```
P0 短链 / 分享链接   —— 服务端每次跳转重发新鲜凭证，可访问性最高
P1 直链 + 新鲜 token —— 尽快使用
P2 过期直链          —— 重新获取凭证，不要试图换参数救过期 token
P3 内容已删除 / 真 404 —— 无解
```
