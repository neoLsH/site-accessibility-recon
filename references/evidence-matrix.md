# 证据矩阵：实验设计与非确定性

结论的可信度不取决于推理有多顺，而取决于**你能不能指出哪一个变量被单独改过、对照是什么**。

---

## 四个实验维度

| 维度 | 取值 | 用来回答 |
|---|---|---|
| 客户端栈 | 原生 curl / curl_cffi(chrome\|safari\|firefox) / node undici / python requests / headless chromium / 真实浏览器 | 边缘是否按传输栈判定 |
| 身份 | UA 族（桌面 Chrome / 移动 / Safari）、Client Hints、语言、时区 | 是否按身份字符串判定 |
| 凭证 | 匿名 / 暖态（首访后）/ 带 token / 带登录态 | 是否按凭证判定 |
| 路由 | 主文档导航 / 同源 XHR / 移动页 / 短链 / API | 是否按请求语义或资源判定 |
| 出口（可选） | 出口 A / 出口 B、直连 / 代理 | 是否按 IP 信誉判定 |

**核心技巧**：固定三个维度、只动一个。两个维度同时动，结论不可归因。

## 最小可用矩阵

先跑这张表，基本能定性 80% 的站点：

| # | 客户端 | 身份 | 凭证 | 预期回答 |
|---|---|---|---|---|
| 1 | 真实浏览器 | 默认 | 匿名 | 对照组：目标内容长什么样 |
| 2 | 原生 curl | 同 UA | 匿名 | 传输栈差异 |
| 3 | curl_cffi chrome | 同 UA | 匿名 | 是否纯 TLS 指纹 |
| 4 | curl_cffi safari | 同 UA | 匿名 | 是否只放行特定浏览器指纹 |
| 5 | node undici | 同 UA | 匿名 | **生产 HTTP 路径**是否可行 |
| 6 | headless chromium | 同 UA | 匿名 | 运行时是否被识别 |
| 7 | headless chromium | 移动 UA | 匿名 | 身份规则 |
| 8 | 上述最优客户端 | 最优身份 | 带 token | 业务层是否还挡 |

`scripts/client-matrix.sh` 覆盖 2–6；加 `--selector <css>` 会输出 `content_region_len`，加 `--passes 3` 可看翻转率。它不覆盖 1、7、8（需要浏览器与凭证）。

## 结果记录格式

一行一条观测，便于 diff 与回放：

```csv
ts,client,identity,route,egress,http,bytes,final_url,content_region_len,marker,note
```

- `content_region_len`：**内容区**可见文本长度，不要用整页长度。
- `marker`：命中的风控特征（响应头字段、凭证属性、页面文案、跳转路径）。
- `note`：是否重试、是否换出口、是否暖态。

## 对照组的三个层次

1. **真实浏览器**：证明“这个 URL 本来有内容”。
2. **已知可用客户端**：证明“这个环境本来能过”。
3. **自身基线**：同一客户端改动前的表现。

改动后如果“基线组也变差了”，说明你的改动引入了新 tell，或者环境本身在漂移（限频、部署、灰度）。

---

## 节流：最容易自欺的一环

连续探测会触发按 IP 的频率降权，表现为“越测越差”，于是你把限频误判成“指纹被识别”。

- 请求之间留间隔（秒级起步），不要背靠背连打。
- 用非重叠时间窗，避免缓存与限频叠加。
- 同一出口被降权后，静置再测；必要时换出口验证“是 IP 问题还是客户端问题”。
- 探测脚本默认 `--delay`，不要提供“连打 100 次”的默认行为。

---

## 非确定性统计

同一 URL 跨次翻转，说明这是**概率门**。

- 至少 3 个 pass，每 pass 之间留间隔。
- 报 **min / median / max** 与**翻转次数**，不报单点。
- 样本要**全量无偏**：只复测“上次失败”的用例，会被暖上下文系统性高估。
- 小样本 + 暖上下文 = 最典型的假阳性来源。

**噪声必须单列**

| 类别 | 处理 |
|---|---|
| 5xx / 网关错误 / 超时 | 基础设施噪声，不计入“被反爬” |
| 内容不存在 / 已删除 | 态 C，不计入分母或单独一列 |
| 降级软拦截 | 计入可访问性失败，但完整性维度单独统计 |

---

## 机制验证 vs 效果验证

| 问题 | 证据 |
|---|---|
| 机制是否触发？ | 内部计数 / 阶段耗时 / 日志字段（例如“检测到墙”“重试执行了 N 次”） |
| 机制是否有效？ | 同一批路由、改动前后的可访问性成功率对比 |

两者必须分开报。机制触发但转化率没变，说明你修的不是主因。
