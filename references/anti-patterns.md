# 反模式黑名单

出现下面这些情况，结论基本是假的。每条给「为什么错」和「替代做法」，按踩到频率排序。

| # | 反模式 | 为什么错 | 替代做法 |
|---|---|---|---|
| 1 | 用两个**恰好都能过**的客户端测，得出「这个因素无关」 | 两个客户端同时满足同一扇门时，实验对那扇门没有分辨力。结论只在「它们都没过」时可信 | 把**生产真实使用的客户端**放进来；过不了的时候再问「差在哪一层」 |
| 2 | 200 就当成功，用整页长度当内容长度 | 降级软拦截、登录墙、空壳页都返回 200；整页长度被导航、页脚、埋点噪声撑大 | 量**内容区**可见文本；`content_region_len` 写进证据行，不用 `bytes` |
| 3 | 只复测「上次失败」的样本 | 暖上下文 + 挑选样本，会把成功率系统性抬高，是最典型的假阳性来源 | 固定 URL 集合全量无偏重测，多 pass 报 min / median / max |
| 4 | 背靠背连打，越测越差就判「被识别」 | 同出口的频率降权会伪装成指纹识别，两者观测上几乎一样 | 秒级间隔 + 非重叠时间窗；静置或换出口复测一次再归因 |
| 5 | 把「站点采集了某个指纹」当成「站点因此判定了我」 | 采集 ≠ 判定，上报 ≠ 同步判定。没有 ablation 就只是相关 | 按 [detection-surface.md](detection-surface.md) 做 E1–E5，拦掉上报或固定产物换出口再看结果是否翻转 |
| 6 | 说「JS 采集了我的 TLS / H2 指纹」 | TLS 握手在任何脚本执行之前完成，页面只能读到 UA、Client Hints、平台、时区这类**自报值** | 网络侧视角看握手（`fp collect` / `fp diff`），运行时视角看自报值与 CDP 痕迹，两者分开归因 |
| 7 | 把 502 / 超时 / 连接重置算进「被反爬」 | 基础设施噪声与策略拒绝对策完全不同，混在一起会让成功率既不可比也不可回归 | 噪声单列计数；三态分诊先排掉链路失败与内容不存在 |
| 8 | 只换 header 不换栈（或反之）就断言原因 | 边缘往往 UA 规则与 TLS 栈**并联**，任一不过都返回同一个拒绝页 | UA × TLS 交叉矩阵；两闸正交时，单变量实验会看起来「没效果」 |
| 9 | 拿到空内容先怪反爬，没先排除抽取下游 | 选择器没命中、容器后来才渲染、字段被改名，都会表现成「空」 | 先跑 [triage-and-gates.md](triage-and-gates.md) 的样本类型 1 判别序列：容器不存在 / 容器为空 / 抽取丢失 |
| 10 | 把站点内部常量写进档案或仓库 | site id、hash、签名密钥、具体 Cookie 名会随仓库扩散，且与结论无关 | 档案里只记「有签名参数、短时效」这类**机制描述**；原始值留在不入库的 `recon/` 工作区 |

## 还有一条：假装有结论

本轮 P0 三件（闸门图、证据矩阵、站点档案）不齐，就写「本轮无结论 + 卡在哪一步」，不要用「大致是反爬」补空。
明确写「这条路由当前无解」比无限试错更有价值。
