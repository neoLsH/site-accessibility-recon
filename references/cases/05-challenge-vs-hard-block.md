# 案例：挑战页 vs 硬阻断（CDN 保护）

> 已脱敏：不保留站点标识、域名、厂商产品名与 Cookie 名。

## 现象

一批被标记为“被 CDN 拦截”的域名，表现看起来完全一样：都返回拦截页。但实际有本质不同的两类。

## 实验

用同一套 stealth 浏览器分别访问 8 个域名：

| 结果 | 数量 | 说明 |
|---|---|---|
| 根本没被发挑战，直接 200 | 3 | 常规 stealth 就够 |
| 被发挑战，等待/交互后通过 | 3 | 需要处理挑战（其中 managed 模式耗时可达数分钟） |
| 硬阻断，403 | 2 | 拦截页是“访问被拒绝”，没有可交互元素 |

对 2 个硬阻断域名换用真实浏览器复测：**仍然 403**（其中一个换真实浏览器后降级为 managed 挑战，但挑战元素定位不到）。

## 结论

- **挑战（challenge）**：可以通过等待或纠正上层信号来通过，属于“你的客户端看起来可疑”。
- **硬阻断（hard block）**：出口信誉 / 区域 / WAF 规则直接拒绝，属于“你这个来源不被接受”。堆指纹伪装无解，杠杆是换出口或走合规渠道。

这两类的表象都是“拦截页”，但一个在指纹层，一个在出口层。

## 可迁移规律

1. **先分类，再动手。** 看拦截页是否携带可交互挑战、看响应头与状态码、看厂商特征，判断是 challenge 还是 block。
2. **硬阻断用真实浏览器复测。** 真浏览器也过不去 = 不是指纹问题，别再投入伪装。
3. **挑战处理是最后手段。** 先修上层（指纹自洽、出口、请求语义）让挑战不下发，比每次点击挑战更稳。
4. 这类结果是**时点样本**，不是稳定良率。CDN 的策略、你的出口、模型版本都在变。

## 置信度

observed + mechanism（分类确证）；良率不具外推性。
