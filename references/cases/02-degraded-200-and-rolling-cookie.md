# 案例：降级 200 与一次性滚动凭证

> 已脱敏：不保留站点标识、域名、厂商产品名与 Cookie 名。

## 现象

内容详情页的正文就在 SSR 里，干净出口直取 200、130–420KB，无需 JS。但服务端渲染集群批量访问时，大量返回 200 且“内容为空”。

## 三档响应

边缘 WAF 对所有请求给出三档之一：

| 档 | 表现 |
|---|---|
| ① 放行 | 200，完整 SSR，正文容器齐全 |
| ② **降级软拦截** | 200，元信息（标题/OG/描述）齐全，但**正文容器被抽空**；同时种一枚有较长有效期的标记 Cookie |
| ③ 硬拒绝 | 非标准状态码 + 交互式挑战页（混淆 JS 计算 Cookie），非 JS 客户端无解 |

第②档是核心陷阱：**它返回 200，且整页看起来“有内容”**。

## 决定性实验

1. **整页长度不可用**：取一个降级页，整页可见文本 6639 字符（完整页 35476，正文区 28837）。这个量级已经超过很多真实短文，任何整页阈值都无法同时放过短文、拦住空壳。
   → 唯一稳健信号是**正文容器的可见长度**（完整约 28837，降级趋零）。

2. **TLS 栈是站点特例**：`curl_cffi impersonate=chrome/edge` 稳定被硬拒绝（Chrome/Edge 指纹被定向拉黑），而原生 `curl`、`node undici` 都是 200。
   → 与上一个案例正好相反：**这个站的 HTTP 抓取路径反而是最优解，不要换成浏览器指纹仿真。**

3. **短窗限频**：单出口连打约 6 次即塌成硬拒绝，静置约 1 分钟恢复。降级档②在限频态也会中招。

4. **凭证是否可复用**：
   - 冻结成功的 Cookie 后只读重放：第 1 发正常，**第 2 发立刻被硬拒绝**。逐个单条 Cookie 隔离测试，无一单独携带“清关”能力。
   - 改成写回链（每跳把响应 `Set-Cookie` 存下、下一跳原样回放）：突发 6/6 全正常，同刻无 Cookie 的对照从第 2 发起被拒绝。
   → 机制是**服务端每次响应重新计算并下发一枚一次性 nonce**，只对下一跳有效。客户端零计算，只需回显。
   - 链可跨 60s 空闲存活，因此可分钟级缓存。

## 结论

- 完整性判定必须量正文容器，不能用整页长度。
- 一次性 nonce 很可能与 IP / 会话绑定 → 与“每请求轮换出口 IP”的并发模型**直接冲突**。要用这条杠杆，必须按 IP 粘滞 + 串行。
- 换干净出口仍是前提：差 IP 连首请求都过不去，起不了链。

## 可迁移规律

1. **200 ≠ 成功。** 降级软拦截是独立的一档，必须专门识别。
2. **完整性信号要绑到内容容器，并且按路由生效**，否则会误伤其他页面。
3. **先判断凭证是静态还是滚动一次性**，再设计并发。冻结重放失败不等于“Cookie 没用”，可能只是用错了复用方式。
4. 同一类站点，TLS 栈的最优选择可能完全相反。**每站实测，不要套模板。**
