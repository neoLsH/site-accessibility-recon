# 案例：CDP 痕迹、延迟重定向与概率门

> 已脱敏：不保留站点标识、域名、厂商产品名与 Cookie 名。这是“自己留的痕迹比目标站的检测更致命”的典型案例。

## 现象

问答/话题类页面在有头真实浏览器下匿名可看，但经自动化浏览器访问时，大量被重定向到登录/验证页。同时“可用率”指标在不同口径下从 21% 到 59% 飘忽。

## 三个独立问题

### 1. 身份自洽做到极致，墙还在

先按常规思路对齐运行时身份：UA 从 Mac 改成与内核真身一致的 Windows、平台与 Client Hints 对齐、WebGL 厂商、时区、语言、`screen ≥ outer ≥ inner` 几何、`webdriver=false`。全部验证自洽后复测：**问答/话题墙依然存在，指标回到基线**。

**结论：自洽是必要条件，不是充分条件。** 指纹对齐只是消掉一个 tell，不是判决条件。

### 2. 真正的杠杆：自己启用的 CDP 域

按“先审计自己”的顺序检查自动化客户端，发现每次初始化都无条件调用了 `Runtime.enable`，而代码里**并不订阅任何 Runtime 事件**，只用 `Runtime.evaluate`（不依赖 enable）。这是一次零收益纯泄漏。

机理：页面可以通过在 `Error.stack` 上埋 getter 探测——客户端开启 Runtime 后，为 `console` 事件生成参数预览时会访问该 getter，于是页面知道“有人开了 inspector”。

决定性对照：同一份探测脚本打两个 target，**开启 Runtime 的 target 读到 `ACCESSED`，不开启的读到 `none`**。

删掉这个调用后：

| 路由 | 改动前 | 改动后 |
|---|---|---|
| 豁免路由 | 100% | 100% |
| 话题型路由 | 约 0–5% | 批量 83% |
| 问答型路由 | 约 3–5% | 批量 15%，安静全量 37.5% |

**结论：判别信号“客观存在”不等于“应用层够不着”。** 先查自己开了哪些域、订阅了哪些事件，再谈内核层。

### 3. 登录墙是客户端跳转，检测必须等

墙不是服务端 302，而是主文档先返回 200，`DOMContentLoaded` 之后页面 JS 才把 `location` 改到登录页。

于是“导航完成即读一次状态”的检测在**重定向落定前**就放行了，后续的重试逻辑根本没有触发。证据：绝大多数“墙”样本的重试阶段耗时只有约 2ms（空转）。

修法是加**有界 settle 轮询**（每 300ms 复查最终 URL 与页面状态，上限 3s，内容区足够长则提前退出），并把同一判定复用到重试循环内部，防止“短暂非墙随后又跳走”被误判为成功。

复测：墙样本中 46/47 触发了重试（修复前 20/22 空转），问答路由均值从首屏地板 13% 抬到 43%。

## 指标为什么飘

| 口径 | 数值 | 问题 |
|---|---|---|
| 原始字段 | 44% | 登录墙在预热后渲染出更丰满的引导文案，被判为“有内容” |
| 修正口径 | 21% | 叠加文案信号 + 最终 URL 标记识别墙页 |
| 合并报“硬墙” | 59% | 把 502 网关错误计成了可用 |

**虚高 2 倍。** 且这是两类错误叠加：内容评估器看长度、URL 启发式只匹配单一关键字，漏掉了实际落地的其他变体路径。

## 可迁移规律

1. **先审计自己的自动化足迹**（启用了哪些 CDP 域、订阅了哪些事件），它是应用层可改的、且常常是最大杠杆。
2. **判定前先 settle**。客户端重定向让“导航完成”不等于“状态落定”。
3. **概率门要报区间。** 同一 URL 跨 pass 翻转率高达 37%，单点估计没有意义；只复测失败样本会被暖上下文系统性高估。
4. **指标虚高要审计。** 登录墙、导航壳、广告填充都会让“有内容”判定失真；必须用文案 + 最终 URL + 内容区长度三重信号。

## 置信度

机制确证（对照实验 + 修复后空转归零）；效果按路由拆分后确证，问答路由仍为概率门，未达上限。
