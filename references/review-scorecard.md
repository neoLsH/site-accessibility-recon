# 诊断质量评分卡

一次排查结束时，用它给**这次诊断**打分：结论站不站得住，而不是文档写得好不好。

一条铁律：**做题的 agent 不给自己打分。** 评分必须由一个没有参与排查的独立 reviewer agent 完成，它只读交付物，不看推理过程、不看作者的自我评价。

---

## 五个维度（总分 100）

| # | 维度 | 分值 | 测什么 | 怎么测 |
|---|---|---|---|---|
| 1 | 证据绑定 | 30 | 每条结论能否指到具体实验行 | 逐条结论找对应的证据矩阵行 / 命令 / 产物；找不到扣 6 分/条，扣完为止 |
| 2 | 单变量与对照 | 20 | 改动是否只动一个因素，对照是否还在 | 检查矩阵里是否存在「两列同时不同」的行（每条扣 5）与缺失的对照组（扣 10） |
| 3 | 置信度标注 | 20 | observed / mechanism / efficacy 是否用对 | 抽查 3 条结论：只有现象却标 mechanism 扣 8/条；把「机制触发」写成「问题解决」扣 8/条 |
| 4 | 反例与不可解 | 15 | 是否记录被证伪的假设、是否敢写无解 | 有「误判 → 被哪次实验推翻」的记录 +8；有明确写「当前无解」的路由 +7 |
| 5 | 可复现性 | 15 | 别人能否重跑 | 抽 2 条结论要求给出完整命令与样本范围并实跑：能跑且结论一致 +8，样本范围写清 +7 |

## 等级

| 等级 | 分数 | 含义 |
|---|---|---|
| A | ≥85 | 结论可直接驱动执行侧改配置 |
| B | 70–84 | 可用，薄弱维度已标注 |
| C | 55–69 | 只能当假设用，落地前必须补实验 |
| D | <55 | 不成立，回到分诊重做 |

## 执行流程

1. **交付物齐全**：闸门图、证据矩阵、`profile.yaml`、报告（P1 可缺，缺了要写明）。
2. **独立 reviewer**：给它交付物目录 + 本评分卡，不给对话记录。
3. **实跑抽检**：从结论里随机抽 2 条，按报告里的命令重跑，看结论是否可重复。抽检优先选「机制」和「有效」级别的结论——那是最贵的错。
4. **产出** `recon/<代号>/REVIEW.md`（写在工作区，不入库）。

## REVIEW.md 模板

```markdown
# 诊断质量评分

**总分：NN/100 · 等级X** | 评分日期：YYYY-MM-DD | reviewer：独立 agent（未参与排查）

| 维度 | 得分 | 判定摘要 |
|------|------|---------|
| 证据绑定 | NN/30 | 3 条结论无对应证据行：…… |
| 单变量与对照 | NN/20 | 第 5 行同时改了 UA 与出口 |
| 置信度标注 | NN/20 | 「指纹被识别」只有现象，标成了 mechanism |
| 反例与不可解 | NN/15 | 记录了 2 次误判推翻过程 |
| 可复现性 | NN/15 | 抽检 2 条：1 条复现、1 条因限频不可复现 |

## 未通过项与返工建议
- ……
```

## 反作弊

- reviewer 不知道主 agent 认为哪条结论最重要，避免只给重点章节打分。
- 抽检结论由 reviewer 随机选，不由作者指定。
- 两条结论的复现结论不一致时，直接判「可复现性」为 0，并在 REVIEW 里贴两次输出的差异。
- 分数只用于决定「能不能落地」，不用于对外宣传。

## 与 `self-check.py` 的分工

| | `scripts/self-check.py` | 本评分卡 |
|---|---|---|
| 对象 | 仓库本身 | 一次具体诊断 |
| 时机 | 每次提交 | 每轮排查结束 |
| 性质 | 确定性检查，可用 CI 卡 | 需要独立 agent 判断 |
| 失败后果 | 不能发布 | 结论不能落地 |

仓库结构合规不等于诊断结论成立，两者都要过。
