# 对策阶梯

原则：**先找不需要对抗的方案，再找便宜的对策。** 多数“反爬问题”的最优解不在反爬层。

## 阶梯

| 级 | 手段 | 何时用 | 成本 | 影响面 / 风险 |
|---|---|---|---|---|
| S0 | 换数据源：官方 API / RSS / sitemap / 移动页 / 短链 / 开放数据 | 永远先试 | 极低 | 无 |
| S1 | 修请求语义：Header 自洽、导航改 XHR、cookie 双通道、路由替换 | 有/无某 header 结果翻转 | 低 | 站点级，易回归 |
| S2 | 换客户端栈：匹配目标站放行的 TLS/H2 指纹 | 同 UA 换栈翻转 | 低 | 运行时级，需覆盖测试 |
| S3 | 运行时卫生：去自动化标记、删无用 CDP 调用、几何与时区自洽 | 真实浏览器能过、自动化不过 | 低–中 | 全局，可能影响所有站点 |
| S4 | 出口策略：干净出口、按 IP 粘滞 + 串行限速、失败换出口 | 换出口即翻转，或出现短窗限频 | 中 | 与并发模型冲突，需架构配合 |
| S5 | 内核身份：UA / 平台 / GPU / 语言 / 时区整体对齐 | 前几级都过、仍有运行时判别 | 高 | 全舰队，需评审 |
| S6 | 行为拟人：鼠标曲线、键盘节奏、滚动模式 | 明确存在行为模型 | 高 | 脆弱、收益递减 |
| S7 | 合法鉴权：官方凭证 / 有权限的账号 | 内容确实需要授权 | 中 | 合规，注意速率与条款 |
| — | 验证码求解、账号池、凭证填充、付费墙绕过 | **不做** | — | 违规 / 不可维护 / 法律风险 |

## 决策树

```
根因定了吗？
├─ 链路失败（错误页 / 代理没挂）   → 修 DNS / 代理；先让 curl -x 通
├─ 传输栈被拦（同 UA 换栈翻转）    → S2：换到被放行的客户端栈
├─ 请求语义（导航被 302，XHR 能过）→ S1：改请求形态 / header / cookie 通道
├─ token 过期（跳登录）            → S0：短链或重新取凭证；换参数无用
├─ 运行时被识别（真浏览器能过）    → S3：先删自己的 CDP 痕迹，再谈 stealth
├─ 短窗限频（越测越差、静置恢复）  → S4：节流 + 换出口；别继续加指纹
├─ 一次性凭证（重放第二发失效）    → S4：按 IP 粘滞串行维持写回链
├─ 硬阻断（干净 IP + 真浏览器也 4xx）→ S4：换出口 / 走合规渠道；堆伪装无解
├─ 内容业务状态（删除/审核/地域）  → 不是反爬：按业务处置
└─ 挑战页（可交互挑战）            → 先修上层使挑战不下发；求解是最后手段
```

## 几个反直觉的结论

- **“指纹自洽”不等于能过。** 把身份对齐到完美，目标站可能仍然拦。自洽只是消掉一个 tell。
- **“加时长/加重试”多数无效。** 如果是资源没下发，等更久只会拿到同一个空壳。
- **“换出口”不是万能。** 有些站是确定性指纹闸，换 IP 无效；有些是一次性凭证，换 IP 反而断链。先定性再动手。
- **“商业代理 + 解验证码”不是技术方案。** 它把问题从工程变成成本，且不稳定、不可审计。
- **别为单个站点做全局改动。** 站点级问题优先站点级配置；全局改动要有评审与回归。

## 何时停手

出现下列任一情况，应停止在对抗层投入，转为降级方案（换数据源 / 降低频率 / 明确不支持）：

- 已证“干净出口 + 真实浏览器”仍被硬阻断。
- 唯一可行手段需要逆向站点密钥或破解签名模块。
- 对抗手段的维护成本高于该路由的业务价值。
- 方案会显著提升对其他站点的风险（全局指纹改动、共享上下文污染）。

停手不是失败，是成本判断。把“不可解”明确写进档案，比无限试错更有价值。
